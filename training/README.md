# B 题 Skill 开发记录

## 初版依据哪些资料

训练语料来自 2018 年和 2020–2024 年的 B 题、附件与 19 篇论文。我们先核对资料是否齐全，再选每年一篇有代表性的论文精读。整理时分别记录题面要求、论文作者采用的方法、作者报告的结果，以及可以迁移到别题的思路。公式或表格的 OCR 存在疑点时，记录页码和缺口。

最先写进 R1 的是三件事。一是描述做决策时已经知道的信息，特别是与未来信息的界限。二是先检查硬约束，再比较目标。三是把上一问交给下一问的文件和字段写清楚。这些约定同时进入拆题、方法筛选、代码计划及 Python/MATLAB 审查。

## R1 到 R2 · 先确定数据在什么范围内可用

在 2025 B 的第一轮盲测中，异常谱段在报告中被标记，拟合程序还是读入了全谱。后续报告如实留下了不收敛的分支。复盘时我们回看已冻结的代码与输出，再对照展示论文和专家讲评，发现这一问题应在选方法之前解决。

R2 把分析域写进代码计划。使用周期性、平稳性等局部结构之前，先列明有效数据范围、排除依据与结构检验，执行后再核对程序真正使用的区间。为避免把这道题的答案写进 Skill，频段数值、阈值和模型参数留在题目记录里。R2 的发布审计记录了 36 条行为检查。

## R2 到 R3 · 数据对得上，阈值经得住复核

2025 C 留出试做暴露了两个问题。一处解析规则漏掉了 131 行有效记录，拟合依然可以运行。从结果表无法发现输入已被悄悄缩小。另一处是原二元分类在 7 次预先约定的数据切分中有 3 次达不到约束，即使某个常用指标在 7 次切分上都优于基线，也仍需处理这项失败。

R3 要求核对审核、解析、排除和实际使用的数据量，核对总行数的同时检查对象数。主方案和基线原则上使用同一批被评估对象。需要阈值时，在训练部分确定阈值，再用相互隔离的外层切分复核硬约束。对于留待复检或暂缓判定的情况，单独报告覆盖比例。该轮没有适用于 C 题的外部答案资料，结论依据冻结的运行与审查记录。

## R3 到 R4 · 把验证做到最后选中的方案上

2025 A 留出题暴露了两个容易混淆的步骤。搜索时以代理指标提前淘汰候选，可能同时淘汰有用的交互方案。定稿时，已有的稳定性证据有时对应另一个候选。

R4 要求记录筛选保留了哪些可行方案，连续硬约束要有能覆盖完整范围的核查依据。导出前重新核对选中候选及其约束、稳健性和来源。改选方案时，重新检查依赖旧方案的结论和文件。发布时核对了三个 Skill 分发目录的内容，对 R3 既有行为做了回归检查。记录为 54 条行为检查、56 条回归检查和 27 项 Skill 校验全部通过。

## R5 · 补上选方法时最容易略过的问题

R4 能检查方案是否有足够的证据，方法指南仍缺少关于具体题型的取舍。R5 将解法说明接入方法筛选、代码计划和稳健性检查。例如，排队与调度题先区分哪些状态可以等价合并，哪些合并可能丢掉未来的选择。实验题先明确因素混杂和响应定义，再设计能区分竞争模型的追加实验。覆盖题把覆盖、重叠和路程分别核算。

R5 的验证集中在四个数学机制，共 17 项合成用例和反例。全题运行效果需要按具体赛题另外验证。 [R5 解法说明](../versions/R5/docs/R5-review-zh.md) · [验证记录](evidence/R5/R5-validation.json)

## R6 · 让脚本核对文件，不靠手写的通过标记

R6 先修正了审计顺序。一致性检查、完整性检查和最终质量审查按先后执行，前面的检查只读取当前已经存在的证据。需要程序读取的产物统一使用版本化文件格式，推导和文字报告仍然可以用 Markdown。

运行时脚本核对文件摘要、决策引用和选中方案。选中结果或上游输入变化后，脚本会指出哪些冻结结果和报告需要重审。R6 将「已作出结果判断」和「具备提交条件」列为不同状态：失败结果也可以完成审阅，而定稿须另行通过稳健性、完成条件和可复算性检查。保存的 28 项合成测试覆盖了缺失基线、旧格式、含糊的通过标记、内容变化但时间戳相同等情况。
