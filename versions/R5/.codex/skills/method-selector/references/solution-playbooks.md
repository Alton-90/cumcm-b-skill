## 从设计到证据
在现有方法卡和代码计划内记录：当前瓶颈、结构前提、数学变换、保留的真实决策、可能丢失的信息、未经变换的参照、共享评价器、预算与消融。优先比较“有/无这个设计”，不要仅比较两个完全不同模型的总指标后把收益归给某个技巧。
区分等价变换（需证明或条件说明）、有误差界的近似、无保证启发式；经验测试不能替代普遍证明。小例只验证实现/展示机制，不能满足实际赛题的 usable_baseline 要求。

## 执行资源
`../scripts/structural_kernels.py` 提供有限前瞻、已知交点的两圆反射、返工闭环、模型分歧排序四个窄内核。使用 `python structural_kernels.py --self-test --output <path.json>` 运行机制与反例测试。它不包含完整赛题解答，也不保证结构化方法一定优于基线。
按真实任务改写并保存到项目 code/Qx，记录来源与修改；MATLAB/北太天元依照数学定义移植并独立执行。不要用 Python 测试替代 MATLAB 验证。
