# 保留决策机会的状态压缩与有限前瞻

适用于大状态图或短视动作导致后续收益下降的子问。不是“动态题都用DP”。与调度、多人决策、几何调整均可组合。

## 解法核心一：先压缩，再求解
将不产生购买、采矿、服务或观测决策的中间节点压为宏转移；每条宏边保留出发时刻、旅行持续时间、资源消耗、途中合法动作和终点状态。地理最短路不一定资源最优，天气随时间改变时不能只保存距离。
对同一时点/位置/信息状态的资源标签考虑支配：只有当标签A的未来可行动作包含B、收益不低且转移单调时才删B。“资源更多”在负重上限、易腐或不能丢弃时可能更差，因此不能通用逐坐标比较。
检查压缩前后的策略是否能互相映射，至少在小原图验证价值与可行路径一致。无法证明保真则记近似，用全图参照量化损失。

## 解法核心二：有限前瞻代替单步贪心
当动作能改善下一轮的观测/资源/几何状态时，以共享末端评价器搜索H步，只执行首步，再更新状态。比较H=1与更长前瞻，报告每步展开数和实际目标；末端启发式不是可采纳界时不得据此宣称全局最优。记录收益优先还是终态误差优先，避免混用目标。

## 信息与交互边界
未知天气只能使用当时观测和有依据的转移分布。情景树里相同观测历史的动作必须一致；不能先对每条未来轨迹全知求最优再求平均来冒充可执行策略。多人资源/价格互相影响时需联合动作或明确博弈/协同假设，不能套单人MDP。

## 实现交接
输入原状态转移、压缩映射、合法动作、预算、终态价值；输出可重放策略、宏边展开路径、保留/剪除理由和目标值。脚本有限前瞻内核仅支持确定性最大化，需适配真实任务后才能作为基线。

## 证据与验证
2020 B125 可读片段行154–176采用关键地点地图简化，行111–113描述时间/位置/资源递推；其天气推断是作者假设。2022 B035 行574–582比较单步贪心与有限深度前瞻。两者支持“改变表示或前瞻范围”的思路，不证明任意压缩安全。
验证：原图/压缩图同实例对照；反例保留；H=1对照；未知未来信息隔离。不能只验证算法能运行。
